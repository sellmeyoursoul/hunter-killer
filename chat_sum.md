Gated by `const _DEBUG_ASSERT_MOTOR_INVARIANTS := true`. Runs at the end of every tick, checks in order:
  1. NaN/Inf position → immediate trip.
  2. Prolonged airborne (`not _body.is_on_floor()` for >45 ticks, after a 45-tick post-spawn settle grace period) → flags C10 stuck-under-geometry. **Iterated once**: an earlier version used a fixed Y-baseline-vs-current-Y threshold, which false-positived on normal terrain-slope settling at spawn (rabbit legitimately dropped >1.5m onto sloped ground in the first 31 ticks); replaced with the `is_on_floor()`-based check, which is robust to terrain elevation and hasn't false-positived since.
  3. `flee_waypoint` repeating a value from recent history → flags C9 boundary ping-pong. **Iterated once**: the first version compared *every tick's* `flee_waypoint` value against a rolling history of every other tick's value, which false-positived immediately because a latched waypoint is *supposed* to read back identical for its full `flee_waypoint_latch_ticks` duration (normal persistence, not a loop). Fixed by only recording/comparing on genuine remint events (value actually changed from the previous tick), and clearing history whenever `flee_waypoint` resets to `Vector3.ZERO` (flight episode ended) so a new episode's first remint isn't indicted by a stale prior episode's history.
  4. Unblocked `MOVE_FORWARD` with <0.02 net displacement over a 30-tick rolling window → generic silent-stall catch-all (not yet triggered/validated live, but in place).
  - On trip: `push_error()` with creature label + reason + exact state dict (position, tick, offending value), then `_body.get_tree().quit(1)` — halts the run dead on the exact offending tick instead of letting it continue and bury the evidence.
